Clearing the Lock on ACH Processing Features

Do not clear the lock on ACH processing features until you have verified that no one at your organization is engaged in processing any ACH files. If they are, do not use the ACH Clear Lock feature.

To clear the lock:

  1. After ensuring that no users are actively working in any ACH forms, click Clear Lock.

  2. Click Yes to confirm that you want to clear the lock.

  3. Click OK.

Processing ACH for External Payroll

Processing ACH for external payroll (your organization’s clients) involves two forms:

  • ACH Processing: View a summary of ACH transactions ready to send to the bank and create or process batches of transactions.

  • ACH Batch Control: Complete processing for the selected batch.

Note: Note: The first time you open the form each day, you might see a warning message. Click Continue to proceed.

ACH Processing

The ACH Processing form lists all unposted batches (unless you use the filters at the top).

  • The first column indicates the Actions you can take, either to start or finish processing the ACH.

Note: To process multiple ACH files, select the checkboxes that only display for the following actions:

  • Start ACH Process

  • Finish ACH Process

  • Retry ACH Process

When you select at least one action checkbox for processing, Build File displays and the Actions links are disabled. (Click Select All to select all files for processing.)

Important! During multiple file ACH processing, the system locks the ACH forms and displays one of the following warnings when users try to access them:

  • If accessing locked files using the ACH Clear Lock form:

[Image: screenshot]

Click OK to continue, then after one hour users can try accessing the ACH Clear Lock form again to unlock the forms. However, if the system has not finished processing the files another warning displays, “Multi-File ACH has not completed processing. If you clear the lock you could interrupt the creation of ACH files. Are you sure you want to clear the lock?” Click Yes to clear the lock.

  • If accessing locked files using the ACH Processing form:

[Image: screenshot]

Click OK to continue and try again later.

Note: See Performing Multiple ACH Processing for detailed information.

  • The Status indicates whether the files are available or if the batch is in process.

  • The other columns display the ACH Originator Names, the ACH Batch ID (if the batch is in progress), the total number of journals included in that batch, and other relevant totals.

  • If you do not assign an ACH Originator to a bank account and transactions are processed through that bank account, a message displays at the bottom of this form for each missing ACH Originator. For example:

[Image: screenshot]

These messages list the number of journals that would be available for processing, if the ACH Originator was assigned in the Bank Accounts form.

Clicking the ACH Originator Missing link opens the Bank Accounts form where you can add the ACH Originator for the bank account in the ACH Processor ID field on the ACH Setup panel.

Note: Note the following:

  • Once a user creates a batch, you can process the transactions included in the batch into a file and send it to the financial institution.

  • Creating the batch locks the transactions in the batch; any new transactions created when users post payrolls will not be added to the ACH batch, which allows payroll processors to continue working while you work on the ACH batch. Those new transactions wait for a future ACH batch.

The buttons at the top right are available to users who can access the associated forms.

  • Completed ACH Transactions is for reprinting reports, downloading the original ACH file, or reopening the ACH batch to rebuild the file; see Viewing and Rebuilding Files for External Payroll ACH Batch.

  • Hold Management enables you to place direct deposits on hold before sending them to the financial institution, or to release direct deposits from hold so they can then be sent; see Holding/Releasing Direct Deposits (External Payroll).

To process ACH for external payroll:

  1. Specify which transactions to include in the ACH file build using the following filters:
  1. — Use the File Type Limiter to indicate whether you want to build the ACH file with Debits and Credits, Debits Only, or Credits Only. The default is to include both debits and credits.

Note: If your organization has specified an offset account on any of the bank accounts included in the ACH batch, the system creates the offset entry regardless of the selection in the File Type Limiter drop-down. If your bank requires strict credit-only or debit-only files (files with no offsetting entries), then you must ensure that there are no offset entries defined for those accounts.

  1. — Use the Child Support Filter to indicate whether you want to build the ACH file with Child Support and Other, Child Support Only, or Not Child Support transactions. The default is to include all transactions.

  2. — Click Refresh to filter the list to show only the selected transactions. It might take a brief moment for the list to update. For example:

[Image: screenshot]

  1. Click the Action link or the checkboxes (for multiple ACH file processing) on the left for the originator and ACH transactions you need to process.

Note: Note the following:

  • When you click Start ACH Process, the system creates an ACH batch and assigns the journals to that batch. The ACH Batch Control form then opens.

  • When you click Retry ACH Process or Finish ACH Process, the ACH Batch Control form opens.

  • If the batch was put on hold, you can click Review Holds to manage the hold (see Holding/Releasing Direct Deposits (External Payroll)).

  • To start the multiple ACH process, select your files and click Build File, which locks the files. The following message displays, “The Multi-File ACH process will now start. You will receive an email when the process has been completed. Do you want to continue?” Click Yes to run the ACH process. (The ACH Processing form closes.)

  • PrismHR is responsible for defining and setting up the SFTP server for clients when processing multiple ACH files.

ACH Batch Control

The ACH Batch Control form summarizes the transactions included in the batch.

[Image: screenshot]

  1. Click the appropriate button to proceed as needed:
  • Build Review Reports: When you click this button, the system generates the report(s) that you use to review the ACH information for the batch. Once they are ready, you can click the link(s) to view, print, or export the report(s).

The reports are available only while you remain in the ACH Batch Control form. If you exit the batch after running the reports and then you return to it later, you must regenerate the reports to see the output. The data in the reports will not change because the transaction list is locked once you create the batch.

  • Build ACH File: After you build the report(s) and then review them to confirm that the information is correct, click this button to build the ACH files. The system generates the ACH Build Detail Report, any other reports as appropriate for the batch, and the text file(s) for you to download. After a batch posts, the total number of detail lines in the ACH file displays, along with the total number of debits and credits.

Note: There is at least one text file; there may be more depending on the format and the transactions. Send all text files to your financial institution.

Note: Note: Text files can have either the .txt or .csv extension, depending on their format.

  • Reset Batch: This button is available until you build the ACH file. Click this button if there is an issue with the ACH batch and you want to delete it. The transactions in the original batch are released and made available for inclusion in a new batch.

  • Close: Click this button to close the ACH Batch Control and return to the Pending ACH Transactions form.

  • Exit ACH Processing: Click this button to close both of the windows.

Holding/Releasing Direct Deposits (External Payroll)

Source: https://tech-docs.prismhr.com/SP_help/Content/PD/ACH/Admin/ACH_Hold_Management_External.htm Path: PD/ACH/Admin/ACH_Hold_Management_External.htm

Holding/Releasing Direct Deposits (External Payroll)

Use the ACH Hold Review and Maintenance form to place direct deposits on hold before sending them to the bank, or to release direct deposits from hold so they can then be sent to the bank.

After selecting the filter settings and then selecting Find Journals, the form displays direct deposits that are already on hold, not on hold, or both, according to the selected filter settings. You can also filter your view to debit or credit transactions only, or filter to view records for a specific client, bank ID, batch, pay date, or employee.

To place direct deposits on hold:

  1. Set the filter options to see the transactions you need:

  • On Hold Status: Select the status you want to view from the drop-down (Yes, No, Both). The default is Yes.

  • Pay Date: Select a date to see transactions from that pay day.

  • Client: Select one client to see transactions associated with that client.

  • Employee ID: Enter an employee’s ID to see transactions associated with person.

  • Payroll Batch: Select a payroll batch ID to see transactions from that payroll.

  • Bank Account: Select a bank account ID/name to see transactions originating from that financial institution.

  • Debit/Credit: Select which transactions you want to see from the drop-down (Debit, Credit, Both).

  1. Select Find Journals.

The list populates with transactions that match your filter settings, displaying the following information:

  • Hold: The hold status for the transaction. If selected, the transaction is on hold.

  • Journal ID: The ACH journal for the transaction.

  • Bank Account: The bank account ID where the money will be either debited or credited.

  • Type: The account type (checking or savings).

  • Company: The client ID associated with the transaction.

  • Payroll: The payroll ID for the payroll that included the transaction.

  • Pay Date: The date of the payroll that included the transaction.

  • Employee ID: The employee ID, if any.

  • Name: The employee name, if any.

  • DB/CR: Specifies whether the transaction was a debit or a credit.

  • Routing: The ABA routing number (also called a transit number) for the checking account where the money will be either debited or credited.

  • Amount: The amount of the transaction.

  1. You can change the Hold status for individual transactions as needed by selecting or deselecting the Hold setting. You can also:

  • Click All On Hold to place all transactions in the list on hold.

  • Click All Off Hold to remove the hold status from all transactions in the list.

Note: Note: You cannot place a transaction on hold if it is in an ACH batch.

  1. Click Save to save any changes, then click OK in the confirmation message that notifies you of the number of records that changed.

  2. When you are finished, click the Close button or [Image: screenshot] to exit the form and clear the ACH Lock.

Deleting a Hold

You can remove holds on direct deposits in the system.

Note: The Delete button only displays when the On Hold Status is set to Yes.

To remove a hold from the system:

  1. Set the On Hold Status to Yes, then select Find Journals. The list of journals on hold displays.

  2. Select a journal that displays in the list.

  3. Click Delete. A warning displays:

[Image: screenshot]

  1. Select Yes to remove the hold on the selected journal.

Creating or Modifying an ACH Journal

Creating or Modifying an ACH Journal

Use the ACH Journal Edit/Entry form to enter a new ACH journal or modify or delete an existing ACH journal.

[Image: screenshot]

To enter a new ACH journal or modify an existing ACH journal:

  1. Enter the Company ID of the client that the ACH journal will debit or credit. The Journal field and the Create New Journal option both activate.

  • Enter a Journal ID if you want to modify an existing ACH journal. The ACH journal information populates the form.

  • Click Create New Journal if you want to create a new ACH journal.

  1. If you are creating an ACH journal for a specific employee, enter or select the Employee ID. Leave this field blank if the ACH journal is for a client. (Note: If you do not enter or select an employee, the HSA options in the Checking/Savings/HSA field (see step 7.) do not display for client-only transactions.)

Note: After entering or selecting the Employee ID, if you try to change it a message displays, “Please cancel and start new entry to change Employee.” Click Cancel and re-enter the ACH journal information.

  1. Enter the Effective Date for the journal, which is the date the account should be debited or credited.

  2. Enter the ID of the payroll Checking Account where the debited funds will be deposited or the credited funds withdrawn.

  3. From the Debit/Credit drop-down, indicate whether the journal is debit or credit:

  • Debit: The transaction will draw funds from the client or employee’s account.

  • Credit: The transaction will deposit funds into the client or employee’s account.

  1. Enter the Amount to debit or credit. To create a prenote transaction, enter 0.

  2. From the Checking/Savings/HSA drop-down, indicate the receiver’s account type:

  • Checking

  • Savings

  • Employee HSA to Savings or Employee HSA to Checking, depending on whether the employee’s direct deposit accounts are set to Savings or Checking, respectively

  • Company HSA to Savings or Company HSA to Checking, depending on whether the employee’s direct deposit accounts are set to Savings or Checking, respectively

After selecting one of these options, the system automatically populates the account information and the account type.

Note: The HSA options only display in the Checking/Savings/HSA field if the selected employee has HSA set up in their Deposit information on the Employee Details form.

After making a selection, if you’re doing a client-only transaction the Default Checking Account Transit and Account Numbers panel displays.

[Image: screenshot]

Note: This panel also displays for employee transactions, but only if the employee does not have direct deposit setup in the system.

  1. Enter one of the following appropriate values:

  • ID of the account in the From Checking Account field

  • Client ID in the From Company field

  • Client location in the From Location field

The default ABA Transit Number and the DFI Account Number populate for the value that you entered.

  1. If the selected employee or client has a checking or savings account, the system automatically populates that account number in the Transit Number and DFI Account Number fields.

  2. If the ACH journal pays an invoice, enter the Invoice Number.

  3. Select ACH on Hold if you want to place the journal on hold.

Note: Note the following when working with journals on hold:

  • If you place one or more journals from a reopened batch on hold, the system removes those journals from the original ACH batch and places them in a new batch.

  • Any consolidation of amounts with other journals in the original batch will be undone.

  • If you choose to remove the journals from hold and process the new batch, the system does not apply a duplicate payment to the client invoice. (The system assumes that the invoice was updated when the first ACH file was built, but for some reason the funds were not actually received.)

Important! It is the user’s responsibility to ensure that the system did not process a debit or credit in the original file before reopening an ACH batch and building a new file with any of the original journals. Any duplicates that were already paid in the original file will be paid again.

  1. Select Suppress Cash Accounting if you want to suppress generating the accounting journal for this transaction.

  2. You can enter Change Comments as needed if you are modifying an existing ACH journal.

  3. Click Save.

Note: Before saving a new ACH journal, if you defined a Miscellaneous Item of ACHSUSP (ACH On Hold/Charge Suspense account) on the G/L Setup form, you must define a G/L account associated with that item. Otherwise, the system displays the following error message when you try to save the journal, “The ACH Suspense Account must be defined at System / Change / G/L Setup to save this record.”

To view audit logs:

  1. Enter or select the Company ID.

  2. Enter or select the Journal.

  3. Select Audit Logs. The File Audit form displays.

Note: The Audit Logs link does not display if you do not have access to the File Audit form. To gain access, you must manually add this form to your user role.

To delete an existing ACH journal:

  1. Select the Company, then select the Journal for deletion. The journal’s information displays.

  2. Click Delete. A warning displays:

[Image: screenshot]

  1. Select Yes to permanently erase the record from the system.

  2. Click Close. The system releases the ACH lock.

[Image: screenshot]

Overview of the Pre-ACH Process in PrismHR

Source: https://tech-docs.prismhr.com/SP_help/Content/PD/ACH/FrontMatter/Overview_PreNote_Process.htm Path: PD/ACH/FrontMatter/Overview_PreNote_Process.htm

Overview of the Pre-ACH Process in PrismHR

Typically, you use pre-ACH processing to protect your organization from unacceptable situations with high-risk clients. You transmit a prenote—a non-dollar entry to alert the receiving bank that an ACH transaction is forthcoming—that allows you to verify that there are no problems with the forthcoming transaction, or resolve any issues that might be revealed by the pre-ACH process. This assures that your organization does not lose money on transactions that would not be fulfilled by a client.

The system sends the pre-ACH file a number of days (usually 5–7) ahead of the regular ACH file. The amount you transmit in the pre-ACH can be equal to either:

  • An arbitrary figure, or

  • The average of the last n regular payrolls run (for example, the average of the last 5 regular payrolls).

Pre-ACH and Floating Deposit

The system uses the pre-ACH amount to “settle out” on the invoice. For example:

The average of the last five invoices for a client is $1120.50. Your organization processes regular payroll runs on Thursday for Friday pay days.

You elect to perform pre-ACH processing five days before the payroll runs, therefore, you transmit a pre‑ACH on Mondays.

When you process the actual payroll on Thursday, for Friday’s pay date, the system then “settles” the balance. If the client’s actual payroll is $1100.00, the system sends them a $22.50 credit. If it is more, the system sends an ACH charge to them for the balance due.

Essentially, the pre-ACH processing allows your client companies to have a “floating deposit” of their average payroll, which is always in transit. However, they get to use that floating deposit each week.

Bounced Transactions

As part of the process, your accounting department must ensure any pre‑ACH that does not clear (or “bounces”) is marked immediately. After they check the bank’s list of bounces each morning, the accounting department must then:

  1. Handle any “bounced” ACH accounts.

  2. Set the value of the Payroll Processing Through Date field to reflect that the accounting department has handled/entered all of the bounced ACH files received from the bank that day.

See Locking the Payroll Processing Through Date.

After the accounting department sets the Payroll Processing Through Date field, you can process or post any pre‑ACH prenote.

Timing of Pre-ACH Process

PrismHR runs the pre-ACH process once a day, the first time a user opens the ACH Processing or the ACH Processing (Internal Payroll) form. While this process runs, users will typically see a message that reads “Please wait - processing Pre-ACH.”

The pre-ACH process will not run again on the same day unless a user sets up pre‑ACH on a pay group that did not have it before. The system will run it again the next time a user opens one of the forms. The system will not duplicate any transactions if it runs the process more than once in a day; it only creates new transactions.

Important Considerations for Pre‑ACH Processing

You would not want to send a pre-ACH on Monday when the payroll department is likely to complete the payroll processing on Tuesday for the Friday pay day. If the pre-ACH processing exposes on Wednesday that the transaction will not be properly fulfilled, it is too late to recover from that.

  • If the financial institution is delayed in notifying you of an upcoming problem identified by the pre‑ACH process, you run the risk of processing a payroll that will ultimately bounce. In such cases, you will have only collected (or refunded) the difference from what you thought you were getting in the pre‑ACH run.

  • If you administer the process carefully, however, you can limit your risk, especially where ACH bounces are predictable at two days or fewer.

Your organization must decide when each pay group should use pre-ACH processing. The process is a rule based on pay groups, not clients. You must select the One Payroll/Pay Group option in the Client Details Payroll tab so that the system correctly assigns the credits for pre-ACH processing. (Selecting this option ensures that PrismHR always processes weekly and biweekly payrolls separately, even on weeks where they pay on the same day.)

If your organization decides to implement the pre-ACH processing feature for the first time, you should begin slowly to ensure that it behaves as desired.

ACH Lock Errors

There are two possible error messages that can prevent a user from running an ACH process in PrismHR due to the processes being locked.

Error 1: ACH Is Locked at a Different Session

ACH is locked by {user’s name} at a different session. Locked on {date} at {time} Continue?

This error occurs when a user is disconnected while running an ACH process and attempts to continue after logging back in.

It also displays if the user is logged into two or more different sessions (such as having PrismHR open in two windows or tabs at the same time) and they attempt to run any of the ACH processes in both of them.

Solution: The user can regain control of the ACH processes by clicking Yes.

  • If the user had only one session open, they can continue with the ACH process they wanted to run.

  • If the user had more than one session open, they can continue in the active session and they will lose control of the ACH process in any other sessions.

Error 2: ACH Is Locked

ACH is locked by {user’s name} Locked on {date} at {time}

This error occurs when another user is (or was) running one of the ACH processes.

Solution:

Make sure that the user named in the error message is not actually engaged in an ACH process or working in any ACH menu option. If they are, do nothing.

Note: Note: If they were disconnected while running one of the processes and did not attempt to continue where they left off, then it is safe to clear the lock.

  • Payrolls set to Pay On-Demand ignore the settings in the Amounts Excluded from Direct Deposit panel.
