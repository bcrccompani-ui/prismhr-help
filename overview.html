Dates

Source: https://tech-docs.prismhr.com/SP_help/Content/Shared-Files/Navigating/Dates.htm Path: Shared-Files/Navigating/Dates.htm

Entering Dates

The system provides several ways to enter dates.

  • The date picker opens when the cursor is in the date field.

  • To enter the current date, type t or T and then press Tab.

  • Type the date. The final format is MM/DD/YYYY, but you need to type only some of it and then press Tab. For example,

  • When you enter M/D, the system populates the leading zeroes and the current year.

  • When you use dashes instead of slashes, the system converts them to slashes.

  • When you enter the month and day and only the last two digits of the year, the system completes the four-digit year.

  • To enter a date that is a specific number of days in the past or future, use the minus or plus symbol and the number. For example,

  • If the date is 90 days in the future, enter +90 and then press Tab. On September 1, the result is November 30.

  • If the date was 10 days in the past, enter -10 and then press Tab. On September 1, the result is August 22.

Data Mapping

Source: https://tech-docs.prismhr.com/SP_help/Content/Shared-Files/Navigating/Display_Data_Mapping.htm Path: Shared-Files/Navigating/Display_Data_Mapping.htm

Displaying Data Mapping Details

The Display Data Mapping form shows you where information is stored in the database. This helps, for example, when you need to know the file and the field names to select tables and properties for Informer reports.

This form is available from the Actions menu of most system forms.

To learn where information is stored in the database:

  1. Navigate to the appropriate form in PrismHR.

  2. Open the Actions menu and select Display Data Mapping. The Data Map form opens, listing the fields in the form and the corresponding information.

  3. Make a note of the information you need.

  4. In Informer, open the Mappings tab and then select the Table Name that closely matches the File Name.

The PrismHR file names have a period and Informer names have an underscore. For example, AD.CONTACTS matches to AD_CONTACTS.

  1. Match the attributes to find the Informer property names.

“Global” and “Company”

Source: https://tech-docs.prismhr.com/SP_help/Content/Shared-Files/Navigating/Global_Company.htm Path: Shared-Files/Navigating/Global_Company.htm

“Global” and “Company”

The definitions of “global” and “company” vary, according to the way your organization is using PrismHR.

  • If your organization is a professional employment organization (PEO), administrative services organization (ASO), or other service provider, the term “company” refers to one of your clients, and “global” pertains to the system as a whole (all of your clients as a group).

  • If your organization is a single corporation, both terms are synonymous and refer to your organization as a whole: the entity or organization using the system.

  • Sometimes “system” is used in place of “global” or it refers to a feature that pertains to the system as a whole.

Source: https://tech-docs.prismhr.com/SP_help/Content/Shared-Files/Navigating/Reports.htm Path: Shared-Files/Navigating/Reports.htm

Accessing Reports

Each user can have access to different reports. The Reports menu lists the reports that are available to you. The options available for each report may differ.

  • Use the Selection Criteria to determine which data the report displays. Some options allow only one value.

  • Use the Sort Options to determine the order in which information displays. Some reports include multiple sort options that enable you to select a primary sort, a secondary sort, and so on.

After you select the options, click Run. The report displays the data.

Use the Actions drop-down list to print, share, or save the report.

About Benefit Imports

Before you can begin importing benefits, you must first follow the multi-step process for setting up group benefit plans. You set up group benefit plans at the system level, but you can administer them at the client level.

Overview

PrismHR has provided another, more limited, method for accessing the PrismONE ID User Administration screen. This menu item, grants access to the PrismONE ID profile for the employee being viewed in the Employee Details form in PrismHR which, by default, limits access to employees that the user can already see (See Security Considerations below).

Problem

Because access to PrismONE ID’s User Administration component was only available to people with read-write access to the User Maintenance form in PrismHR, password and access support tickets had to be escalated to top tier support.

Solution

A PrismONE ID account can be linked to multiple user profiles within your PrismHR system.

An Example

ABC PEO has three PrismHR systems

  • ABC (production)
  • ABC.DEMO (for demo & testing)
  • ABC.CORP (for paying ABC’s own staff)

Jane works for ABC PEO as a payroll processor.

She has a Service Provider (SP) account in the production system (ABC). She also has an employee account at ABC.CORP. Additionally, Jane helps to train new employees in ABC.DEMO. To do this training, Jane has set up multiple, fictitious employees. To make it easier to access all of these users, Jane has linked all of them to her PrismONE ID profile. She can now access all of them with a single set of credentials and can move between the three systems without needing to log out and back into each of them.

John also works at ABC PEO. John is being trained as a 1st tier support rep. As part of John’s training, he has been given a user account that has access to all of the fictious in ABC.DEMO. John has also had the new action menu item added to his role, enabling him to access the PrismONE ID User Admin screen for the fictitious employees in ABC.DEMO.

Because John can access the PrismONE User Administration screen for the fictious employees in ABC.DEMO, he can access Jane’s PrismONE ID profile. This gives John the ability to change Jane’s username, password, and MFA settings. It also gives John the ability to disable or enable Jane’s PrismONE ID account.

Mitigation

  • In the above case, Jane should make sure that any employees in the demo system are not linked to that same PrismONE ID profile that she uses for her Service Provider access or her own Personal Employee account access in ABC.CORP.
  • This feature is not recommended for WSMs who can access the Core PrismHR system.
  • Limit the roles that contain this feature and only assign those roles to users who have their security set up properly.
  • If you don’t feel that you fully understand these security considerations, please reach out to your PrismHR CSM to arrange a consultation. Do not assign this form to any roles until you are certain you understand its scope and limitations.

Chapter 1 Introduction Use this document to learn about PrismHR’s support for single sign-on (SSO) between PrismHR products and third-party vendor products.

Single Sign-On Single sign-on (SSO) enables users of PrismHR products to link directly to and from third-party vendor products, without the need to sign in to the product multiple times. The PrismHR products are: • PrismHR • Employee Portal (EP)

Intended Audience These contents are intended for: • Vendors who want to link from their product to PrismHR products. • Service providers who want to configure their systems to support SSO for PrismHR and third-party vendor products. • PrismHR employees who need to configure single sign-on. Developers implementing SSO should be familiar with the terminology referenced in this document, as well as the technology used to build the product, so they can integrate it with the PrismHR products. We recommend that an administrator perform this setup at the service provider. This administrator should be familiar with the specific products that require configuration.

Requirements To use the PrismHR single sign-on features: • Third-party vendors must alter their software to enable it to communicate with PrismHR. • On-premise service providers must have already purchased and installed the PrismHR API.

Single Sign-On Guide © 2026 PrismHR 5 Chapter 2 Overview

Chapter 2 Overview There are two single sign-on mechanisms: inbound and outbound. • Outbound: Users first log in to one of the PrismHR products. Then, they click a menu item or a link to access a third-party vendor product. • Inbound: Users first log in to a third-party vendor product. Then, they click a menu item or a link to access a PrismHR product.

Security Security for both the outbound and inbound mechanisms relies on an out-of-band conversation between the two servers: a source and a target. In this context, an out-of-band conversation is one that does not include the user’s machine. • Outbound mechanism: The source is the PrismHR product (PrismHR or Employee Portal) and the target is the third-party vendor product. • Inbound mechanism: The source is the third-party vendor product, and the target is PrismHR or Employee Portal, depending on the user. When the request is made to go from the source product to the target, PrismHR creates a token that is valid only once. Once the user follows a link to the product, this token is validated and deleted. If the user needs to access the destination product again, they must log back in to the system. Even if they save the URL, it will not work during subsequent attempts.

Note: OAuth calls this a nonce token, which means “number used once”.

Outbound Mechanism In the outbound mechanism: 1. The user logs in to a PrismHR product (PrismHR, Employee Portal). 2. This user clicks a menu item or link to access a third-party vendor product. The PrismHR system stores a token in the database, sends the token to the user machine, and redirects the user to the third-party server. The token is embedded in the redirect URL as a query string parameter.

Single Sign-On Guide © 2026 PrismHR 6 Chapter 2 Overview

  1. The third-party product receives the token from the URL, then takes that token and makes a direct call to the PrismHR system. It asks for the identity of the user associated with the token. The PrismHR system sends one of two responses: • Valid = Confirms that the user logged into the PrismHR system and then sends the user’s information: name, company ID, user type, and so on. For more information, see User Information Returned. • Null = The PrismHR system did not recognize the token. With the returned information, the third-party product can identify the user and log them in.

California Quarterly Reports

California is a client reported state. Every employer operating in the state of California need to report specific information periodically to the Employment Development Department (EDD) of the State of California. Use this form to generate the following reports:

If taxes are due, payment should be submitted with a Payroll Tax Deposit (DE 88 Form). You can file the DE 9 Form electronically or via paper.

This is a required report that must be completed by California employers on a quarterly basis.
