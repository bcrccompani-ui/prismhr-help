Processing Payroll

Use the Process Payroll form to enter time sheet information, calculate the payroll, finalize the payroll, run the *Payroll Validation Report* and the *Payroll Audit Report*, update employee and payroll records, review/download errors and warnings, and print the vouchers. For example:

**Important!** The output recorded in the *Payroll Audit Report* is generated using artificial intelligence (AI), so please review all output for accuracy, completeness, and appropriateness before using it.

    Payroll Calculation Logic

    The payroll calculation process includes the gross wages and calculates the employee contribution based on the Benefit Rules and value assigned to the Benefit Plan for Gross % of Wages.

    On the Benefit Rules form, if a benefit plan uses the Percent of Gross Wages value, then while calculating the contribution towards the Employee portion of premium, if Max Contribution has been defined for any Benefit Rule, then it will ignore the Max Contribution value. You must also set The Contribution rule amounts made by Company or Employee field to Employee for the payroll process to include gross wages.

    The logic to determine the Percent of Gross Wages being used is as follows:

  • If the Employee Benefit Rule Overrides form uses the Percent of Gross Wages value, then:
  • the value in the Percent of Gross Wages field on the Employee Benefit Rule Overrides form will be used to calculate the Percent of Gross Wages or else it will use the value assigned on the Group Benefit Plans form to calculate Percent of Gross Wages.
  • If the Employee Benefit Rule Overrides form does not use the Percent of Gross Wages value, then:
  • the value in the Percent of Gross Wages field on the Benefit Rules form will be used to calculate the Percent of Gross Wages or else it will use the value assigned on the Group Benefit Plans form to calculate Percent of Gross Wages.

    • The payroll calculation is as below:

  • Once the Percent of Gross Wages value has been determined, this value is used to calculate the Contribution Amount for the Employee portion of the premium.
  • If the Percent of Gross Wages value is not being considered, then the Contribution Amount is calculated for the Employee portion of the premium based on the Benefit Rule grid.
  • If the Percent of Gross Wages value is less than the Calculated Contribution from the Benefit Rule grid, then the Percent of Gross Wages is used as the contribution towards the Employee portion of premium. The dependent premium is calculated in full by the benefit rule.
  • If the Percent of Gross Wages value is greater than the Calculated Contribution from the Benefit Rule grid, then the Calculated Contribution is used from the Benefit Rule grid as the contribution towards the Employee portion of premium.

    Calculating Payroll Vouchers

    To begin the payroll calculation process, click the Calculate icon (

    [Image: screenshot]

    ) for the payroll. (**Note**: The time sheet entry must be complete to enable payroll calculation.)

    > **Note:** **Note:** The Security Notification dialog displays if you have made changes to sensitive employee information prior to calculating payroll.

    During the payroll calculation process, PrismHR creates a payroll voucher for each employee to be paid in the current payroll as follows:

  • Calculates full gross-to-net earnings
  • Posts any other earnings combined with selected time sheet earnings to one of up to twelve payroll vouchers that could be created for an individual employee
  • Calculates and processes scheduled deductions
  • Calculates and takes payroll taxes
  • Processes any active tax calculation overrides or deduction overrides
  • Creates billing vouchers
  • Calculates accounting
  • Calculates benefits and benefit deductions
  • Accrues paid time off registers, if any
  • Applies FLSA ruleset, if applicable

    • > **Note:** **Note:** If the pay date is on or before today’s date, you might be prompted to enter an authorization code; [see Authorization Code for Backdated Payroll](Backdate_Authorization_Code.htm).

    Finalizing the Payroll

    When you are sure all the information for the payroll batch is complete and accurate, finalize the payroll by clicking the Finalize icon (

    [Image: screenshot]

    ).

    During the Finalization process, PrismHR gathers the data from the vouchers created during the calculation of the payroll and finalizes each item to the appropriate register. The system creates a permanent record of the payroll within its files.

    Once the payroll is finalized, PrismHR considers it to be complete and creates another payroll for this client and pay group. The system cannot calculate or finalize more than one payroll for the same client at the same time.

    Reports and invoices designated to be printed at the completion of the payroll print immediately to your designated printer. The system sends checks and direct deposit advices, as well as any garnishment checks, to a print file.

    > **Note:** Note the following:

  • If you pass the ACH threshold limit during payroll processing a message displays in the job progress window on the Process Payroll form. In addition, the following warning displays in the Errors and Warnings panel after payroll calculation finishes, "The payroll is over the ACH threshold limit. You must clear the ACH hold before payroll displays in the ACH file. Delaying this action could delay releasing funds to employees." (If the ACH threshold limit is null, the message and warning do not display. However, if the ACH threshold limit is set to at least zero (0), the message and warning do display if the payroll is over the limit.)
  • If you have a payroll where all employees receive live checks but the client is paying their invoice using ACH and that invoice exceeds the ACH threshold limit, the system displays a warning during calculation and finalization. At that time, the funds for the client are put on hold if the fees to be taken from the client are over the threshold limit.

    • Finalizing Payroll for Self-Service Worksite Managers and Worksite Trusted Advisors

    Self-service worksite managers and worksite trusted advisors who are restricted from finalizing and printing payroll can indicate that they are ready to send the payroll to a service provider for finalization when they finish reviewing the payroll.

    After self-service worksite managers and worksite trusted advisors successfully calculate a payroll (the payroll must be in INITWARN or INITOK status) the following message displays, "Are you sure you want to submit the payroll for processing?" Make either of the following selections to continue:

  • Yes: The system moves the payroll to the next status and becomes visible to service providers in SuperBatch. In addition, making this selection dims/locks the Time Sheet Entry and Payroll Calculation icons and updates the Payroll Calculation icon's text for all user types depending on the payroll status:
  • INITWARN: *Payroll Calculation: Complete with Warnings, Submitted*
  • INITOK: *Payroll Calculation: Complete, Submitted*

    • **Note**: Selecting Yes does not allow self-service worksite managers and worksite trusted advisors to edit the payroll any further without a service provider resetting it back to them to any status before payroll calculation. After a service provider changes the payroll status back to any status with "TS," the Time Sheet Entry icon becomes available to worksite managers and worksite trusted advisors once again. In addition, if the status is set to TSOKCOMP, the Payroll Calculation icon becomes available.

  • No: The system moves the payroll to the next status and is not visible to service providers in SuperBatch. In addition, making this selection updates the Payroll Calculation icon's text for all user types depending on the payroll status:
  • INITWARN: *Payroll Calculation: Complete with Warnings, Not submitted*
  • INITOK: *Payroll Calculation: Complete, Not submitted*

    • **Note**: Selecting No requires recalculation to submit the payroll for processing.

    Once the payroll is ready for finalization after making a response from the list above, the following occurs for service providers:

  • Yes: The system automatically *updates* SuperBatch, so service providers can post the payroll.
  • No: The system *does not* update SuperBatch, so service providers cannot post the payroll.

    Establishing Information for Processing Payrolls

    You can use the Payroll Control form to establish essential information for processing payroll in PrismHR. There are three types of payrolls that users can process: regularly scheduled, manual, and special/unscheduled batches. You determine the payroll type using the Payroll Type field.

    PrismHR uses the parameters defined in the Payroll Control form to automatically schedule the next batch.

  • Regularly Scheduled: Following the successful completion of a payroll, PrismHR automatically creates a new Payroll Control record for the next regularly scheduled payroll. The regularly scheduled payroll includes time sheets for each employee scheduled to be paid in the payroll. Payroll processors can add or delete time sheets as necessary.

    • > **Note:** **Note:** When deleting a payroll, Full access users have the option of copying saved entries, which can be applied to a new payroll without having to re-import or re-enter the data. After clicking Yes in the first two confirmation dialogs that display when you click Delete in the Payroll Control form, a third confirmation dialog displays, "Do you want to keep the keyed entries and apply them to the new payroll?" Click Yes to copy all saved entries and charge dates (including entries in the deduction columns) into a new payroll batch. Clicking No produces a blank timesheet. (Previously accepted Pay Rates and Leave Requests remain unchanged.)

    In addition, if you try to delete a payroll where a reverse wire transfer journal exists an error displays, "Payroll <*XXX*> can not be deleted as the ACH journals have already been created."

  • Special/Unscheduled: Enter a payroll for specific pay groups.
  • Manual: Enter a supplemental or unscheduled payroll for one or more employees.

    • > **Note:** **Note:** You can also use the form to view in progress or past payrolls. However, you cannot edit posted payrolls, and you cannot create regularly scheduled payrolls.

    Identifying Pay Groups or Employees

    Use the third panel to identify who is associated with the payroll, either Pay Groups or Employees. For example:

  • Pay Groups: Regularly Scheduled or Special payrolls. For example:

    • [Image: screenshot]

    a.Enter the Pay Group associated with this payroll. The Description displays.

    b. — Enter the Period Start date, which must be the first day of the payroll period for this payroll. The system uses this to select the time sheets to pay; the system selects only time sheets with a charge date within the period entered here.

    c. — Enter the Period End date, which must be the last day of the payroll period for this payroll. The system uses this date to select the time sheets.

    d. — Enter the number of Weeks Worked during the period, which the system uses to produce the Weeks Worked amount on the Quarterly FUTA/SUTA reports.

    e. — Enter the Deduction Period on which the pay date falls. The system uses this during payroll processing to take the appropriate standard payroll deductions for the employees in this pay group. The system takes only the deductions defined for this deduction period.

    f.Enter the Pay Period number. The default populates based on the Period Start date.

    g. — Select the Alt Pay Period to use for this pay group. This overrides the period assigned to the pay group; for example, you can use the Annually option to calculate taxes on an annual basis for all wages paid to employees on the payroll, overriding the employee's regular taxation basis as set by their pay group.
