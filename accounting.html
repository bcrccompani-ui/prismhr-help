Resetting Posted Payroll Account Journals

You can use this feature to reset payroll account journals that have been posted to external accounting, so they can be exported again.

You can reset three types of journals:

  • Export journals

  • Third Party journals

  • Cash-transfer journals

The External Accounting Reset panel displays:

  • Select: Use these checkboxes to select individual line(s) to process

  • Journal ID: ID of the payroll account journal

  • Post Date: Date the payroll account journal was posted

  • TranDate: Date of the payroll (transaction date)

  • Co No: Employer ID

  • Debit Amt: Total debit amount

  • Count: Debit count for date and employer

  • Credit Amt: Total credit amount

  • Count: Credit count for date and employer

  • Debit Total: Totals of the Debit Amt and Count columns

  • Credit Total: Totals of the Credit Amt and Count columns

To reset payroll account journals, do the following:

  1. Click Back Office. Select External Accounting Reset from the Operations|Action menu.

  2. Do the following in the External Accounting Reset form:

Field Description
Start Date/End Date Enter or select the Start Date and End Date.
Accounting Type Select one of the following Accounting Type options: - Cash Post: For journals created by entering cash receipts. - Third Party Post: For journals created by posting a third party deductions batch. (If an error occurs while posting third party deductions, select this option to view the posted journals for that type so you can re-post.) - Journal Post: All other journals. Note: Select the option based on the form where you want to re-post.
  • Cash Post: For journals created by entering cash receipts.
  • Third Party Post: For journals created by posting a third party deductions batch. (If an error occurs while posting third party deductions, select this option to view the posted journals for that type so you can re-post.)
  • Journal Post: All other journals.
  1. Depending on the option you selected, a panel displays the selected journals posted during that date range for individual payroll account journals. For example, cash posts could look similar to the following:

About A/R Aging Buckets

About A/R Aging Buckets

PrismHR supports data aging and uses two sets of buckets. The buckets represent aged accounts receivable data. Many organizations have a different set of rules for their operational use (operations) than what is required by financial standards (finance).

Note: Note: If your organization uses more than five buckets, you must print the reports on legal-sized paper. The system supports up to seven total buckets.

Example Setup

For example, consider an organization that mostly uses cash. An open balance over seven days old is a cause for concern and review. The organization’s banking relationships, however, want to review the receivables in standard increments of 30-, 60-, and 90-days. To facilitate reporting, the organization built two sets of buckets:

  • Operations records

  • Standard financial records

The organization has these Operations buckets:

  • Current (0)

  • 1–7

  • 8–14

  • 15–21

  • 22+

The Finance buckets are standard:

  • Current (0)

  • 1–30

  • 31–60

  • 61–90

  • 91+

Maintaining Aging Buckets

Your organization can define AR aging buckets for your own use (operations) and for reporting purposes (finance) in the Aging Bucket Maintenance form.

You can create up to seven buckets.

[Image: Aging Bucket Maintenance form, showing the standard fields: Bucket Code, Age Based On, and the Buckets grid with columns for Desc Line 1 and 2.]

To maintain AR aging buckets:

  1. Access the Aging Bucket Maintenance form (found in the Back Office menu under Accounts Receivable|Change).

  2. Select the Bucket code:

  • Operations: aging bucket for use by your organization.

  • Finance: aging bucket for reporting to financial institutions.

  1. Select the Age based on, either Invoice Date or Due Date. The system calculates the actual due date based on the AR term code.

Next, define each bucket. You must define the buckets in order, with the newest at the top and the oldest at the bottom.

  1. Enter the number for each of the Buckets, for example, 60.

  • This must be an integer, and the number represents the aging; any document this age or newer will go in this column.

  • Define the last bucket as 99999. The system recognizes that value as the final tier.

  1. Enter the first line of the stacked heading for the aging report in Desc Line1, for example, 31 - 60.

  2. Enter the second line of the stacked heading for the aging report in Desc Line2, for example, Past Due.

On the report, this example would display as:

31 - 60

Past Due

  1. Click Save.

Configuring AR Terms

Source: https://tech-docs.prismhr.com/SP_help/Content/PD/Accounting/Action/AR_Terms_Code_Maint.htm Path: PD/Accounting/Action/AR_Terms_Code_Maint.htm

Configuring AR Terms

Your organization can define different terms for dealing with different customers or vendors, such as Net 0 or Net 10th Prox. Each term is represented by a terms code.

[Image: AR Terms form open to terms code Net0. The Due Type is set to days and the number of days is set to 0.]

[Image: AR Terms form open to terms code Net10P. The due type is set to Prox, last day of the month is set to 25, and number of days is set to 10.]

To define AR terms codes:

  1. Access the AR Terms form (found in the Back Office menu under Accounts Receivable|Change).

  2. Enter the Terms Code. If you are creating a new code, use a code or ID that best represents the accounts receivable terms used by your organization. For example:

  • Net0 for a net zero term (due immediately)

  • Net10P for net 10th prox term (due by the tenth of the month)

  1. Enter a clear and concise description of the term in the A/R Terms Desc field.

  2. Select the A/R Terms Due Type:

  • Days - Terms due after a certain number of days

  • Prox - Terms due on a day of the following month

  1. If you selected Prox, enter the cutoff day in the field that begins “What is the last day of the month…”. This defines the cutoff date for the due date. Payments for invoices through this date are due by the specified day of the following month.

If the due day is 10, the due date is the 10th of the following month. The cutoff day is the 25th of the current month, therefore:

  • Invoices dated between June 1 through June 25 are due on July 10.

  • Invoices dated between June 26 and June 30 are due on August 10.

  1. In the Number of days or day of the month field:

  • For Days, enter the number of days when the invoice is due.

  • For Prox, enter the day of the month when the invoice is due.

  1. Click Save.

Entering Cash Receipts

Use the Cash Receipts form to enter new batches of cash receipts or edit existing ones and upload a file for import.

Note: Note: When you enter a debit invoice that is greater than the deposit amount, you must enter credit invoices first. Otherwise, the system generates an error.

Using Post and Clear Buttons

  • Post: Click to post the cash receipts batch when the deposit is complete.

  • Clear: Click to save the cash receipts batch. The system adds it to the list of open batches at the top of the Cash Receipts form.

  • To open the Cash Receipts Import form to upload a file for import and view errors that occurred during cash receipts imports or view successfully imported rows, click the Import icon ( [Image: screenshot] ). (See Importing and Posting Cash Receipts.)

Configuring AR Customer Details

Use Customer Details to maintain the customer address and contact information for collection purposes, view the current representation of aging for the customer, and edit the credit limit rules.

The form displays the information for the currently selected client.

To access this form, open the Back Office menu and select Customer Details under Accounts Receivable|Change.

[Image: Customer Details panel for an example client. Shows the client address and the A/R Terms Code set to “Net 10th Prox”]

To set up basic customer details:

  1. Locate the Customer Details panel at the top of the form. The Customer number displays.

  2. Edit the customer name and address as needed.

  3. Enter the Customer Group used to prepare agings to which this customer belongs, if any.

  4. Select the A/R Terms Code.

Contacts

Use the Contacts panel to maintain customer contacts.

[Image: Customer contacts panel showing one row labeled “MAIN NUMBER” along with an example phone number.]

  1. For each contact at the customer:

  • Enter the Contact Name.

  • Enter the Phone number.

  • Enter the Extension, if any.

  • Enter the Email address.

Aging

The Aging panel displays your organization’s operations aging information for the customer.

[Image: Example of the Aging panel, showing different aging bucket descriptions in each row (read only column). The Aging Buckets column is empty.]

  • The Bucket Desc column shows the descriptions for each of the buckets.

  • The Aging Buckets column displays the amount in each bucket.

Credit Details

Use the Credit Details panel to maintain credit rules, if that applies to this customer.

[Image: Customer Credit Details panel showing the available fields. Max Credit is set to 45,000 and in the Limit Rules grid, there is a row for a “Flat Amount” also equal to 45,000.]

  1. The panel displays the customer’s current Credit Limit, Balance Due, and Available Credit.

  2. Enter the Max Credit, which is the maximum credit limit allowed. If you leave this field blank, there is no credit limit.

  3. Select Client On Hold if this customer is on a credit hold. The option indicates a manual hold, not the automatic hold.

  4. Set the limit rules:

  • Select each of the Limit Rules that determines what the credit limit should be and how far the client is allowed to go outside those limits, if at all.

  • Enter the Limit Amt that applies to the limit rule.

  1. For each limit review:

  • Enter the Limit Review Date when you conducted the review of the credit limit.

  • Enter the Limit Review By name or user name.

  • Enter the Limit Review Description/Override.

If the customer is put on credit hold, enter OVERRIDE and then any additional comments.

Otherwise, enter any comments about the limit review.

  1. Click Save.

Invoices

Users can click the Invoices button to view the client’s invoices. See Reviewing Invoice Information for details.

Using the External Invoice Post Feature

When users process a payroll batch, the system looks at the pay date and the employer ID and adds it to a file of transactions. All payrolls processed with the same pay date and employer ID are compiled into one entry in the Export Invoice Update form (part of the External Invoice Post feature). When you look at the data in the report, it is listed by client number and invoice date. The import file includes the details by account number.

The External Invoice Update form displays:

  • Select: Use these checkboxes to select individual line(s) to process

  • TranDate: Date of the payroll (transaction date)

  • Co No: Employer ID

  • Invoice Amt: Total invoice amount

  • Count: Invoice count for date and employer

  • Receipt Amt: Total receipt amount

  • Count: Receipt count for date and employer

  • Available Invoice Total: Totals of the Invoice Amt and Count columns

  • Available Receipt Total: Totals of the Receipt Amt and Count columns

  • Show Receipts: Use this checkbox to display ACH receipts for the following accounting types:

  • Great Plains / Dymamics (with or without Build Account #’s)

  • Quick Books (with or without Build Account #’s)

  • Peach Tree / Sage (with or without Build Account #’s)

  • Itacct (with or without Build Account #’s)

The following example illustrates the External Invoice Post form.

[Image: This is the External Invoice Post form]

  • To view the External Invoice Detail report for only one transaction date at a time, click the TranDate.

  • To view the External Invoice Detail report for one or more than one transaction dates, select them and click the Report button. The Report button will display only after at least one line item (TranDate) has been selected.

This report is not available in any menu. If you might need to refer to it again in the future, print or save a copy of the report.

[Image: The External Invoice Detail report]

  • To create the file that you will use to import the information into your financial accounting system:

  1. Select each line that you want to process, or Select All to include all lines.

  2. Click Process Batch.

  3. Click Yes in the confirmation message to proceed with the process, otherwise click No to return to the Export Invoice Update form.

  4. If you clicked Yes, the system builds the external journal posting file.

  5. When the process completes, click Close. (The button enables when the process is complete.)

[Image: Process dialog for “Building External Invoice Posting File”]

Note: Note: All dates and times in PrismHR are Central Time.

  1. When the process completes, click Close.

  2. The action of saving the file varies depending on your browser preferences. Some typical examples are that the system will prompt you with a Save As dialog, or merely ask you to confirm that you want to save the ZIP file, or it might simply download the file to your default location.

Once you save the file, the processed transaction(s) no longer display in the Export Journal Update form.

  1. When you navigate to the location where you saved the ZIP file. Inside it contains text files with the format INVmmddyyERID.xxx (where mmddyy is the month, day, and year, ERID is the employer ID, and xxx is the type of file created).

Reviewing Auto Reconciled Checks

Use the Reconciliation Report for Auto Recon to review the reconciled checks in the reconciliation data file your organization is currently processing see Importing Auto Reconciliation Data.

To run the Reconciliation Report for Auto Recon:

  1. Open the report parameters form (found in the Back Office menu under Operations|Report).

  2. Enter the Checking Account No. you entered in Auto Check Reconciliation Load when you started the process.

  3. Enter the appropriate dates in the Beginning Date and Ending Date fields.

The report displays all the checks in the data file with pay dates that were in the specified date range. The report displays the reconciliation error. Some examples of discrepancies are:

  • A Check number that does not match an open check number in the system.

  • An Amount Cleared value that does not match the value in the system.

Notes About Common Issues

  • If the wrong file was loaded accidentally or if the file is loaded with the wrong format, the Check Reconciliation Edit Report will display garbage data, possibly including references to check numbers that do not exist. If that is the case, return to the Auto Check Reconciliation Load and begin again. Be sure to select the option to clear out the existing in the reconciliation file.

  • The automatic reconciliation process does not allow a check to be reconciled more than once. If you attempt to use a check number that has already been reconciled, the report displays the error Invalid Check Status: R.

  • If you know a check listed in the report with an error is actually correct and should be reconciled, use the manual reconciliation feature.

Checks that were included in the reconciliation data file that do not have errors will be reconciled when you post them.

Clearing Outstanding Checks

Use Stale Check Reconciliation form to clear outstanding checks.

To reconcile stale checks:

  1. Open the Stale Check Reconciliation form, found in the Back Office menu under Operations|Action.

  2. Enter the Checking Account ID. This is the number that represents an account in PrismHR and may not match the actual bank account number. The Account Number displays.

  3. There are two ways to enter stale check numbers:

  • If you know the numbers, you can enter each of them in the Check Number column in the table.

  • You can also click the Import Stale Checks button to retrieve a list of all outstanding checks for the specified account and select the ones you want to reconcile.

After you click the button, the system retrieves a list of all uncleared checks. This can take a little while, depending on how many outstanding checks exist for the checking account.

[Image: Import Stale Checks form. An Ending Check Date has been entered and a number of checks display in the table.]

You can limit the checks in the list by entering a Beginning Check Date, an Ending Check Date, or both.

  • If you enter a Beginning Check Date, the system filters out any checks with a pay date before that date.

  • If you enter an Ending Check Date, the system filters our any checks with a pay date after that date.

Note: Note: There are different ways to enter dates. For example, if you want to enter a date that is 180 days in the past (about six months), enter -180 in the appropriate date field. See Entering Dates for more information.

After entering the date, press the Tab key. The list filters to match the criteria you entered.

  • Enable the Select checkbox for each check you want to include, or use the Select All checkbox to select all checks in the list.

  • Click Accept. The system returns you to the Stale Check Reconciliation Entry form and the selected checks populate the table.

  1. Click Update on the Stale Check Reconciliation Entry form. The system marks the selected checks as reconciled with a stale date of the current day.

  2. The system prompts you to choose whether to view a report of the checks marked as reconciled.

  • Click Yes to view the Stale Check Register by Check Number Report. The report displays the stale checks that you just reconciled. Use the Actions drop-down to print, share, or save the report.

  • Click No if you do not want to see the report. The system displays a reminder that stale checks are not account for in any way, and that you must do journals based on the reports to update your ledgers.

When you are finished, the form clears.

Rebuilding Registers

Use the Register Rebuilds form to rebuild Form 941 Tax Registers, Company Tax Registers, or All Tax Registers for a Year. You can also Rebuild Tax Basis Transfer from Successor.

Note: Note: This form does not use Client Access Group Security.

Adding User Permission to Register Type Options

To display the Register Type options for users in the Register Rebuilds form, you must add the following forms to the user role(s) in the User Roles form:

  • 941 Tax Registers: 941 Register Rebuild Security Control Form (HRPY.WORK*941.REBUILD.SECURITY.STUB)

  • Company Tax Registers: Company Register Rebuild Security Control Form (HRPY.WORK*COMPANY.REBUILD.SECURITY.STUB)

  • Rebuild All Tax Registers for a Year: Tax Register Rebuild Security Control Form (HRPY.WORK*TAX.REBUILD.SECURITY.STUB)

  • Rebuild Tax Basis Transfer from Successor: Transfer Tax Rebuild Security Control Form (HRPY.WORK*TRANSFER.REBUILD.SECURITY.STUB)

For example, this user role is set up to allow a user to rebuild company registers and tax basis transfers, but that user cannot rebuild 941 registers or all tax registers:

[Image: User Roles form showing “Full” and “Deny” access for various register rebuild forms.]

See the PrismHRSystem Administration Guide for more information about defining user roles.

Rebuilding 941 Tax Registers

The 941 tax registers are used to generate data contained on the 941 worksheet report and the 941 schedule R report. These reports show the tax liabilities for Federal Income Tax as well as the Employee/Employer portion of OASDI and Medicare. The 941 register rebuild process corrects data that is contained in this register.

To rebuild 941 registers:

  1. Click Back Office. Under Operations|Action, select Register Rebuilds.

  2. Select Tax - 941 Tax Registers from the Register Type drop-down.

  3. Select a Year against which registers are rebuilt.

  4. Select All if you want to rebuild the 941 Tax Registers for all employers OR

  5. Select Select Employers if you want to rebuild the 941 Tax Registers for selected employers. Click the Employer ID hyperlink and add one or more employers.

  6. Click Rebuild. The system cautions you about the implications of rebuilding registers.

  7. Click Yes to proceed with the rebuild. A progress window displays.

Rebuilding Company Registers

Rebuilding company registers rebuilds all tax registers for the specified company. This includes Employee and Employer Tax Registers, Employee 401K Registers, Employee Voucher Registers, Employee Benefits Registers, Employee Workers Comp Registers, Employee Deferral Registers, and Employee Voucher Cross Reference Registers.

Note: Note: This form does not use Client Access Group Security.

To rebuild company registers:

  1. Click Back Office. Under Operations|Action, select Register Rebuilds.

  2. Select Tax - Company Tax Registers from the Register Type drop-down.

  3. Select a Year against which registers are rebuilt.

  4. Select a Client ID for Company Register Rebuilds.

  5. Click Rebuild. The system cautions you about the implications of rebuilding registers.

  6. Click Yes to proceed with the rebuild. A progress window displays.

Rebuild All Tax Registers for a Year

You can rebuild registers by selecting the type of register from a single form. The Notification process monitors each rebuild process to provide updates. It can take hours to rebuild tax registers. During this process, it is best practice to set the lockout feature to prevent payrolls from being initialized as this can cause incorrect voucher calculations.

This option rebuilds the company, employee, employer, 941, and client federal entity tax registers at one time for a particular year.

To rebuild all tax registers for a year:

  1. Click Back Office. Under Operations|Action, select Register Rebuilds.

  2. Select Tax - Rebuild All Tax Registers for a Year from the Register Type drop-down.

  3. Select a tax Year.

  4. Click Rebuild. The system warns that the data used for payroll and employee pay history will be cleared and asks whether you still want to proceed.

  5. The following database files are involved in this process:

  • EMPLOYEE.TAX.REGISTER

  • EMPLOYER.TAX.REGISTER

  • CLIENT.TAX.REGISTER

  • EMPLOYER.941.REGISTER

  • CLIENT.SUM.TAX.REGISTER

  • TAX.LIABILITY.JOURNAL

  • EMPLOYEE.PAYROLL.REGISTER

  1. Click Yes. The rebuild progress window appears and displays the rebuild process steps. You will receive an email notification when the rebuild process is finished.

Rebuilding the Tax Transfer Basis from Successor

This option rebuilds the tax registers that are created when importing the taxes from successor wages.

To rebuild the tax registers that are created when importing taxes from successor wages:

  3. Select a tax Year.

  4. If you want to clear the register before rebuilding, select Clear Register Prior to Rebuild.

Note: Note: This process only clears the Net Taxable to Another State or Successor and the Net Tax to Another State or Successor fields.

  • EMPLOYEE.TAX.REGISTER

In the system, group benefit plans have accrual accounting attached to them. (Many other systems only track employee contributions to group benefits as they are deducted from employee checks.)

Using the per-batch method is especially useful for a company that performs complex cost accounting using cost centers. The costs are broken out at the source level, which means there is less chance for accounting errors—not to mention less work.

Client Provided and Paid Benefit Plan

Client Provided and Paid Benefit Plan

In this case, the PEO has no cost associated with the plan and has all monies deducted from the employee, decreasing the invoice.

PrismHR users frequently handle these kinds of plans as simple voluntary deductions with a client rebate code attached (for example, see Table 68). This reduces the client invoice by the amount deducted from the employees.

There are some issues handling these benefits as simple deductions, though. Since the PEO does not administer the plan, the client has to notify the PEO how and when to update the amounts to be withheld from each employee’s check. However, if your client is unable or does not desire to keep up with the balances due, you might want to build an “Other” group benefit plan. Building the “Other” group benefit plan automatically activates PrismHR’s built-in arrearage system and allows you to keep track of contributions.

The accounting issue with benefit plans is making the Cost accounting side “go away.” With client sponsored/client paid benefits, the PEO has no liability or cost accounting requirements because the PEO is rebating all the money deducted from employee checks through invoice credits.

For this case, the PrismHR Customer Support Team recommends that PrismHR users create a liability account that is assigned the function of washing through zero value journals. In this case, the Benefit Plan would have both the debit and credit transactions assigned to this zero account.

Also, the premium cost sides of the plan should be set to zero (0.00) costs, as should the billing sides of the plan. You would do this by building a Benefit Plan in Benefit Plan maintenance that showed the premium costs for each plan level (single, single plus one, family, and so on) as zero. In the event some money ever ended up in the account accidentally, the fact that it would exist on the balance sheet would bring immediate attention to the problem.

It accrues the entire benefit payable while deciding which employees are eligible for the benefit—in other words, whether or not the employee makes a contribution against the benefit, the entire balance accrues. The system is capturing the total due to the plan provider.

With this in mind, the selection of the Premium Debit and Premium Credit accounts should ultimately charge the cost of sale account for the debit and the liability account for the credit.

Taxes

If you have created global tax codes, you must create the association of each tax code with a general ledger account. Tax G/L accounts are entered into the system based on state code and tax ID.

  1. Enter the G/L Template for the general ledger distribution template. This template was previously defined.

  2. From the G/L Type drop-down, select Tax.

  3. In the State Code field, enter FG for federal government or the two-character state code (second example below). The system lists each Tax ID and Description in the first two columns. These taxes are either at the federal level (federal income tax), state level (state income tax, SUTA, and so on), or lower (county and local taxes).

For employer-paid taxes, you need both a credit (liability) account and debit (expense) account.

For employee-paid taxes, you need only a credit account because there is no expense to an employee-paid tax.

When a tax is computed, the system looks at the state record to find the G/L codes. If they are not found there, it looks at FG (federal government). Therefore, you should only enter general ledger numbers at the state level if they are different from the ones used for the federal government.

If you want to use only state-level accounting, then leave the FG record entirely blank. That way, the system will inform you if the state is missing codes rather than accepting the federal-level defaults.
